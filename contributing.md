# Contribution Guidelines

---

Ensure your pull request adheres to the following guidelines:

- Add working software a writer can actually open and use. A GitHub repo of prompts or “skills” for a coding agent is not a tool.
- Prefer a short description (one clause) in the same style as the surrounding entries.
- Put the entry in the section that matches what it does. Do not list the same tool twice unless it truly belongs in two places (for example a desktop app that also runs in the browser).
- Link to the project’s home page when it has one; otherwise link to the GitHub repo.
- One pull request per suggestion is easiest to review.

Thank you for your suggestions!

### Updating your PR

A lot of times, making a PR adhere to the standards above can be difficult. If the maintainers notice anything that we'd like changed, we'll ask you to edit your PR before we merge it. There's no need to open a new PR, just edit the existing one. If you're not sure how to do that, [here is a guide](https://github.com/RichardLitt/knowledge/blob/master/github/amending-a-commit-guide.md) on the different ways you can update your PR so that we can merge it.
